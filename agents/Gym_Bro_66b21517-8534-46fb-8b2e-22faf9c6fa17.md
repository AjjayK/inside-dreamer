# Agent: Gym Bro

**ID:** 66b21517-8534-46fb-8b2e-22faf9c6fa17

## Description

# OVERVIEW
A complete workout tracking companion with guided onboarding (routine + equipment selection), daily workout management with progress tracking, and a 7-day calendar editor for customizing your split. Stores your routine, equipment, and workout progress persistently, with daily auto-reset and equipment-filtered exercise libraries.

# KEY FEATURES
- **Onboarding (2 steps)**, Choose from Push/Pull/Legs, Upper/Lower, Full Body, or Bro Split routines with weekly schedule preview. Then select available gym equipment—only compatible exercises appear throughout the app.
- **Daily Workout Dashboard**, Shows today's routine with exercise cards displaying sets/reps, completion toggles, and buttons to view form instructions or swap exercises. Displays progress (X/Y completed) with auto-reset on new day.
- **7-Day Calendar Editor**, View and customize the next 7 days inline. Rest days get 'Add Workout'; workout days get 'Make Rest Day', 'Add Exercise', and 'Reset to Default'. Per-exercise replace/remove actions. Custom overrides persist separately from base routine.
- **Exercise Database**, 5–7 exercises per routine (Bench Press, Squats, Deadlifts, Pull-ups, etc.) with sets/reps/equipment/muscle groups. Step-by-step form instructions for compound lifts. Alternative exercise library grouped by muscle, filtered by your equipment.
- **Persistent State**, Saves selected routine, equipment, onboarding status, daily progress (auto-resets by date), and per-date custom workout overrides across app sessions.

# VERBATIM INSTRUCTIONS
Gym Workout Tracker
Build a gym workout tracker agent with onboarding, daily workout management, and a 7-day calendar editor. The agent should be called 'Gym Bro'

Onboarding Flow (2 steps)
Step 1: Choose a Workout Routine
Present the user with a choice of workout split routines. Include these four:
	• Push/Pull/Legs — 7-day cycle: Push → Pull → Legs → Rest → Push → Pull → Legs
	• Upper/Lower — 7-day cycle: Upper → Lower → Rest → Upper → Lower → Rest → Rest
	• Full Body — 7-day cycle: Full Body A → Rest → Full Body B → Rest → Full Body C → Rest → Rest
	• “Bro Split” (Body-part split, 5 days/week)
	Example 7-day cycle: Chest → Back → Shoulders → Arms → Legs → Rest → Rest
	
Each routine should display its weekly schedule so the user knows what they're signing up for.
Step 2: Select Available Equipment
After choosing a routine, show a multi-select grid of gym equipment options (e.g., Barbell, Dumbbells, Pull-up Bar, Cable Machine, Bench, Squat Rack, Leg Press, Dip Station, Resistance Bands, Kettlebells, Smith Machine, etc.).
The selected equipment determines which exercises are available — exercises requiring equipment the user doesn't have are automatically filtered out from all workouts. The user must select at least one piece of equipment before proceeding.
Allow going back to change routine from this step.

Exercise Database
Workout Definitions
Each routine's workout type (e.g., "Push", "Upper", "Full Body A") should contain 5–7 exercises. Each exercise has:
	• Name
	• Sets (e.g., 4)
	• Reps (e.g., "8-10")
	• Required equipment (list, can be empty for bodyweight exercises)
	• Target muscle group (e.g., Chest, Quads, Biceps)
Populate with real, appropriate exercises for each workout type. Cover major compound and isolation movements.
Exercise Instructions
For key compound lifts (Bench Press, Squats, Deadlifts, Pull-ups, etc.), store step-by-step form instructions (5–6 steps each) that can be shown in a detail modal.
Alternative Exercises
Maintain a library of alternative exercises grouped by muscle (Chest, Back, Shoulders, Quads, Hamstrings, Biceps, Triceps, etc.). Each alternative has a name and required equipment list. These are used for exercise replacement and for adding exercises in the calendar editor. Alternatives shown to the user should always be filtered by their available equipment.

Main Dashboard (Post-Onboarding)
Header
	• Show today's day of the week, the workout type for today (e.g., "Push" or "Rest Day"), and the selected routine name.
	• Provide links/buttons to: View 7-Day Calendar, Change Settings (returns to onboarding), and Clear All Data (with confirmation).
Today's Workout
	• If it's a rest day, show a rest day message.
	• If it's a workout day, show the list of exercises for today. Each exercise card displays: 
		○ A completion toggle (checkbox/checkmark) — click to mark done/undone
		○ Exercise name, sets × reps
		○ A "Replace" button — opens a modal to swap with an alternative exercise targeting the same muscle group
		○ A "Details" button — opens a modal showing target muscle, sets, reps, and step-by-step instructions
Progress Summary
Below the exercise list, show:
	• Exercises completed vs. total (e.g., "3 / 6")
	• Completion percentage
Daily Reset
Completion progress should be tied to today's date. When a new day starts, completed exercises reset automatically.

7-Day Calendar View (Modal/Overlay)
Show the next 7 days (starting from today) in a scrollable list. Each day card shows:
	• Day of the week + date
	• Workout type
	• Whether it's been customized (show a "Modified" indicator)
	• Highlight today's card
Per-Day Actions
	• Rest days get an "Add Workout" button — restores the default workout for that slot if one exists
	• Workout days get: 
		○ "Make Rest Day" — converts the day to rest
		○ "Add Exercise" — opens a modal where the user picks a muscle group, then picks from available alternatives to add (defaults to 3 sets × 10-12 reps)
		○ "Reset to Default" — only shown for modified days, reverts customizations
Per-Exercise Actions (within each day)
	• Replace — swap with an alternative exercise for the same muscle
	• Remove — delete the exercise from that day's workout
All calendar modifications should be stored as custom overrides per date, separate from the base routine definitions. The base routines should never be mutated.

Data Persistence
All of the following should be persisted and restored on app load:
	• Selected equipment
	• Selected routine
	• Onboarding completion state
	• Today's exercise completion progress (tied to current date — auto-resets on new day)
	• Custom workout overrides (per-date modifications from the calendar editor)

Key Behaviors
	1. Equipment filtering is global — any time exercises are shown (today's workout, alternatives, calendar), only exercises compatible with the user's equipment appear.
	2. Custom workouts override defaults — if a date has a custom override, use it instead of the routine's scheduled workout for that day.
	3. Exercise replacement preserves sets/reps — when swapping an exercise, keep the original's sets and reps, only change the exercise name and equipment.
	4. Alternatives exclude the current exercise — when replacing, show same-muscle alternatives that the user has equipment for.
	5. The routine schedule is cyclical — map the 7-day schedule array to days of the week based on the current day.

### getOnboardingContext

**Description:** Returns everything Sidekick needs for conversational onboarding.

**When to call:** At the START of any conversation where the user wants to set up Gym Bro or change their workout settings. Call this BEFORE asking the user any onboarding questions.

**What it returns:**
- isOnboarded: whether the user already has a setup
- currentSettings: their current routine/equipment if onboarded (null otherwise)
- availableRoutines: the 4 built-in routines with names, descriptions, and weekly schedules
- equipmentCategories: all equipment organized by category (Free Weights, Machines, Cardio, Functional)
- memorySuggestions: what Sidekick already knows about the user's fitness preferences (may be null)

**How to use the data:**
1. If memorySuggestions has data, mention what you remember and ASK THE USER TO CONFIRM OR ADJUST — never silently use memory values without explicit confirmation
2. Present routine options conversationally (don't dump a wall of text — describe 1-2 at a time based on what fits the user)
3. ALWAYS ask about equipment explicitly — ask what gym they go to or what they have at home. Even if memory has equipment data, present it and ask the user to confirm or update it
4. Only call setupFromSidekick AFTER the user has explicitly confirmed BOTH their routine AND equipment choices in the current conversation. Memory data alone is NOT confirmation.

**Input Schema:**

```json
{
  "type": "object",
  "properties": {}
}
```

### setCustomWorkoutForDay

**Description:** Replaces an entire day's workout with a custom workout. There are TWO ways to use this:

1. **By muscle groups (PREFERRED):** Pass muscleGroups (e.g. ['Chest'] or ['Biceps', 'Triceps']) and the system will auto-pick the best exercises based on the user's saved equipment. No need to specify individual exercises.

2. **By exercise names:** Pass an exercises array with specific exercise names. Use this only when the user requests specific exercises (e.g. 'just a treadmill run').

If both muscleGroups and exercises are provided, muscleGroups takes priority.

**Input Schema:**

```json
{
```

### setupFromSidekick

**Description:** Full onboarding in one call — saves routine + equipment, generates AI workout plan, and writes today's exercises.

**CRITICAL: You MUST have an explicit back-and-forth conversation with the user about BOTH routine AND equipment before calling this function.** Even if you already know the user's preferences from memory, you MUST still:
1. Mention what you remember and ASK THE USER TO CONFIRM OR ADJUST — do NOT silently use memory values
2. Explicitly discuss the routine choice — ask the user to pick or confirm
3. Explicitly discuss equipment — ask what equipment they have access to, or present what you remember and ask them to confirm
4. Summarize the final choices and get a clear "yes" / confirmation before calling this function

**NEVER call this function without the user explicitly confirming both routine AND equipment in the current conversation.** Getting data from memory does NOT count as confirmation.

**Flow:** 1) Call getOnboardingContext 2) Discuss routine with user and get confirmation 3) Discuss equipment with user and get confirmation 4) Summarize and get final "go ahead" 5) ONLY THEN call setupFromSidekick

**For built-in routines:** Pass routine as 'ppl', 'upper_lower', 'full_body', or 'bro_split'.
**For custom routines:** Pass routine as 'custom' AND provide customDescription (e.g. "shoulder+tricep, 3 days a week" or "chest/back/legs/arms/shoulders with 2 rest days"). The system will figure out the schedule and generate appropriate exercises.

After setup, the user can open Gym Bro and start working out immediately — today's exercises are written right away.

```json
      "items": {
        "type": "string"
```
