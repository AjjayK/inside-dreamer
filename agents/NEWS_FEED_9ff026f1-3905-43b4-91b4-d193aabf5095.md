# Personal News - Product Requirements Document

## Overview
Personal News is a daily news curator that learns your interests and surfaces the stories that matter most to you. It builds a dynamic profile of your passions—then filters global news sources to find the most relevant, highest-quality articles each day. Instead of drowning in generic headlines, you get a curated feed of the stories you'll actually want to read.

## Key Features

### 1. Interest Profile Building
Automatically creates and maintains a profile of your key interests based on your activity, preferences, and past engagement patterns.

**Implementation:**
- On first use, the system queries the user's sidekick to extract interests from their existing memory and context
- Presents suggested interests organized by category (Technology, Business, Sports, Science, Politics, Culture)
- Allows users to select from suggestions or add custom interests
- Stores profile in database for fast access on subsequent sessions
- Profile includes interests array and optional location

**Technical Details:**
- `initializeProfile()` server function calls `sdk.sidekickWithSchema()` once
- Profile stored in `user_profile` table with JSON-serialized interests
- Settings modal allows editing interests at any time
- Updates to profile inform sidekick for memory synchronization

### 2. Daily News Curation
Scans multiple news sources each morning to find articles matching your interest areas.

**Implementation:**
- Daily cron trigger runs at 8am in user's timezone
- `main()` background function orchestrates the curation process
- Creates a sidekick task with detailed instructions for intelligent curation
- Sidekick task autonomously:
  - Searches for headlines matching each interest topic
  - Crawls promising articles for full content
  - Filters for quality and relevance
  - Deduplicates similar stories
  - Ranks by importance to user
  - Selects top 5-8 articles

**Technical Details:**
- Uses `create_sidekick_task()` from sidekicktasks tool
- Sidekick has access to `headlines` tool from news server
- Uses `webcrawl` for fetching full article content
- Checks post history to avoid duplicate articles
- Cron schedule: `0 8 * * *` (configurable in agent.yaml)

### 3. Smart Ranking & Filtering
Ranks articles by relevance and quality, surfacing only the top 5-8 stories you'll genuinely care about.

**Implementation:**
- Sidekick task applies intelligent filtering criteria:
  - Actual relevance to user interests (not just keyword matching)
  - Article quality (depth, credibility, newsworthiness)
  - Source reputation
  - Uniqueness (deduplicates stories about same event)
- Balances coverage across different interest areas
- Prioritizes quality over quantity

### 4. Feed Posts with Summaries
Posts curated articles to your feed with brief summaries, source attribution, and direct links.

**Implementation:**
- Sidekick task creates feed posts using `create_agent_post()` tool
- Each post includes:
  - shortMessage: Article headline
  - Markdown attachment: 2-3 sentence summary + topic tag
  - URL attachment: Direct link to article
  - priority: normal (not urgent)
  - duration: read_once
- Posts appear in user's feed and in the agent UI

**Technical Details:**
- `getCuratedArticles()` server function retrieves posts from last 7 days
- Uses `get_agent_post_history()` tool to fetch posts
- UI parses post content to extract summary, topic, and URL

### 5. Article Bookmarking
Save articles for later reading with a bookmark button on each article card.

**Implementation:**
- Each article card displays a bookmark icon in the header
- Clicking the bookmark saves the article to a dedicated Bookmarks section
- Bookmarked articles persist across sessions
- Bookmarks accessible via sidebar navigation
- Can unbookmark from the Bookmarks screen

**Technical Details:**
- `isSaved` boolean field in `curated_articles` table
- `toggleArticleSaved()` server function toggles bookmark state
- `getSavedArticles()` retrieves all bookmarked articles
- Optimistic UI updates for instant feedback
- Toast notifications for bookmark actions

### 6. Article Archiving
Archive articles to remove them from the main feed while keeping them accessible.

**Implementation:**
- Each article card displays an archive icon next to the bookmark icon
- Clicking archive removes the article from the feed
- Archived articles move to a dedicated Archive section in the sidebar
- Can unarchive from the Archive screen to restore to feed

**Technical Details:**
- `isArchived` boolean field in `curated_articles` table
- `toggleArticleArchived()` server function toggles archive state
- `getArchivedArticles()` retrieves all archived articles
- `getCuratedArticles()` filters out archived articles from the feed
- Optimistic UI updates with immediate visual feedback
- Toast notifications: "Article archived" / "Article restored to feed"

### 7. Enrollment Experience
On first run, displays your interest profile for review and adjustment—add, remove, or modify interests to fine-tune curation.

**Implementation:**
- App checks for existing profile on load
- If no profile exists, shows ProfileSetup component
- ProfileSetup:
  - Displays loading state while querying sidekick
  - Shows sidekick-suggested interests pre-selected
  - Displays suggested interests grouped by category
  - Allows adding custom interests
  - Saves to database when user confirms
- Subsequent sessions load profile from database (no sidekick call)

**User Experience:**
- Clean, guided onboarding flow
- No empty text boxes—uses chips and buttons for selections
- Progressive disclosure of interest categories
- Visual feedback for selected interests
- Single confirmation button to complete setup

## Technical Architecture

### Database Schema
**user_profile table:**
- id (auto-increment primary key)
- interests (JSON array of strings)
- location (optional string)
- preferredSources (optional JSON array)
- hideReadArticles (boolean, default true)
- updateTime, updateTime2 (scheduled update times)
- updateTimeEnabled, updateTime2Enabled (boolean flags)
- refreshStartedAt, refreshCompletedAt (timestamps)
- createdAt, updatedAt (timestamps)

**curated_articles table:**
- id (auto-increment primary key)
- url, title, justification (text, required)
- matchingInterest (text, required)
- ogImage, ogDescription (optional text)
- isRead (boolean, default false)
- isSaved (boolean, default false) - for bookmarks
- isArchived (boolean, default false) - for archive
- createdAt (timestamp)

**suggested_interests table:**
- id (auto-increment primary key)
- interest (unique string)
- category (string)
- displayOrder (integer)

### Server Functions
1. `getUserProfile()` - Retrieves user profile from database
2. `initializeProfile()` - Queries sidekick for user interests (called once)
3. `saveProfile()` - Saves/updates profile, informs sidekick of changes
4. `getSuggestedInterests()` - Returns categorized interest suggestions
5. `getCuratedArticles()` - Fetches recent posts from feed (excludes archived)
6. `markArticleAsRead()` - Marks article as read
7. `toggleArticleSaved()` - Toggles bookmark state
8. `getSavedArticles()` - Retrieves bookmarked articles
9. `toggleArticleArchived()` - Toggles archive state
10. `getArchivedArticles()` - Retrieves archived articles
11. `main()` - Background function for daily curation (exported, called by cron)

### Data Flow
1. **Profile Initialization:**
   - User opens app → Check database
   - No profile → Call sidekick → Display suggestions → User selects → Save to database
   - Has profile → Load from database → Display feed

2. **Daily Curation:**
   - Cron triggers at 8am
   - Load profile from database
   - Create sidekick task with instructions
   - Sidekick autonomously:
     - Searches for news
     - Crawls articles
     - Filters and ranks
     - Creates feed posts
   - Posts appear in feed

3. **User Updates Profile:**
   - Open settings → Edit interests → Save
   - Update database
   - Inform sidekick of changes
   - Close modal → Invalidate queries → Refresh

### Cost Optimization
- Profile: 1 sidekick call on initialization (one-time per user)
- Daily curation: 1 sidekick task per day
- All user interactions use database queries (free)
- Sidekick task optimized to:
  - Run searches in parallel
  - Crawl only promising articles
  - Batch similar operations
  - Focus on top 5-8 results

### Tools Used
- **news server:** `headlines()` - Searches news by topic
- **sidekicktasks server:** `create_sidekick_task()` - Creates autonomous agent
- **posts server:** `create_agent_post()` - Posts articles to feed
- **posts server:** `get_agent_post_history()` - Retrieves past posts
- **webcrawl:** Used by sidekick for fetching article content

## User Journey

### First-Time User
1. Opens Personal News app
2. Sees loading spinner "Building your interest profile..."
3. Sidekick suggests interests based on memory
4. User reviews suggested interests (organized by category)
5. User adds/removes interests as desired
6. User clicks "Start Getting News"
7. Profile saved, sees feed (initially empty)
8. Message: "Your first curated news will arrive tomorrow morning"

### Returning User
1. Opens Personal News app
2. Sees curated article feed
3. Scrolls through 5-8 high-quality articles
4. Clicks "Read Article →" to open in new tab
5. Can click Settings to adjust interests
6. Changes saved, feed refreshes on next curation

### Daily Curation (Background)
1. 8am in user's timezone
2. System loads user profile
3. Creates sidekick task
4. Sidekick searches news sources
5. Filters and ranks articles
6. Posts top stories to feed
7. User sees new articles next time they open app
